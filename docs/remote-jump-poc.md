# 공기계 점프 전송 POC (2026-10-10)

## 구성

- 기존 `/games/motion-poc`의 Canvas 러너를 재사용한다. 별도 게임 그래픽은 만들지 않았다.
- `/games/motion-poc/remote`를 두 기기에서 열어 하나는 **게임 화면**, 다른 하나는 **공기계 컨트롤러**로 설정한다.
- 컨트롤러는 브라우저 `devicemotion`의 중력 포함 3축 가속도를 읽는다. 처음 2초는 정지, 다음 2초는 제자리 달리기를 기준으로 보정한다. 달리기 구간의 상위 5% 가속도보다 충분히 큰 신호가 두 샘플 연속 나타나면 점프 신호를 보낸다. 800ms 재발생 제한을 둔다. 이 판정식은 실제 어린이 데이터로 조정되지 않은 시험용이다.
- 두 브라우저는 같은 Wi-Fi에서 WebRTC 데이터 채널로 직접 연결한다. 서버는 사용하지 않으며, 보호자가 최초 연결 정보와 응답 정보를 복사해 교환한다. 연결 정보의 유효 기간은 해당 연결 세션까지다. 연결이 끊어지면 화면의 게임 입력을 중단한다.
- 컨트롤러는 **점프 이벤트만** 전송한다. 자세 영상이나 연속 센서 원본은 전송하지 않는다. 표시 기기는 점프 이벤트를 받으면 캐릭터 점프를 시작한다. 러너는 점프만으로 피할 수 있는 낮은 장애물만 생성한다.
- `DeviceMotionEvent` 접근에는 HTTPS 또는 localhost의 보안 컨텍스트가 필요하며, 브라우저에 따라 사용자의 센서 권한 허용이 필요하다. 센서 신호가 1.6초 동안 없으면 입력을 중단하고 오류를 표시한다. 연결 정보를 교환하며 다른 앱으로 이동해도 연결 정보는 유지한다. 센서 사용 중 화면이 백그라운드로 가면 센서만 중지하고 다시 보정하도록 안내한다. 가능한 브라우저에서는 화면 꺼짐 방지도 요청한다.

## 연결 순서

1. 표시 기기에서 `/games/motion-poc/remote`의 **게임 화면 → 화면 연결 시작**을 누른다.
2. 나타난 연결 정보를 공기계에 전달한다. 공기계에서 **공기계 컨트롤러**를 선택하고 정보를 붙여넣은 뒤 **연결 정보로 응답 만들기**를 누른다.
3. 공기계의 응답 정보를 표시 기기에 전달하고 **연결 완료**를 누른다. 양쪽에 `연결됨`이 나타나는지 확인한다.
4. 먼저 **점프 신호 전송 테스트**로 전송·렌더링을 확인한다.
5. 공기계를 몸에 흔들리지 않게 고정하고 **움직임 센서 시작**을 누른다. 2초간 서 있고, 2초간 제자리 달리기를 한 다음 점프를 시험한다. 휴대폰을 쥐고 뛰는 사용 방식은 전제하지 않는다.

| 항목 | 결과 | 범위 |
|---|---:|---|
| 브라우저 연결 | 성공 | 같은 Mac의 Headless Chromium 브라우저 2개, 수동 연결 정보 교환 |
| 버튼 점프 전송 → 수신 | 성공 | 수신 화면 `받은 점프 1`, Canvas 점프 반영 |
| 합성 센서 이벤트 → 점프 판정 → 전송 → 렌더 | 성공 | 브라우저에서 정지·달리기·점프 가속도 이벤트를 생성해 `보낸 점프 1`, `받은 점프 1` 확인. 실제 움직임 데이터 아님 |
| 신호 왕복 지연 | 15ms | 같은 Mac에서 버튼 1회. 네트워크·실기기 측정치 아님 |
| 수신 → Canvas 렌더 | 11ms | 같은 Mac에서 버튼 1회. TV 표시 지연 제외 |
| 렌더링 FPS | 60fps | 같은 Mac의 게임 화면 |
| 센서 판정 | 합성 시퀀스 테스트 통과 | 실제 휴대폰, 착용 위치, 어린이 동작은 미측정 |
| 점프 시작 → TV 반응 | 미측정 | 실제 두 기기와 TV 시험 필요 |

## 남은 검증

- 실제 Android/iOS 기기에서 센서 권한, 데이터 빈도, 백그라운드 동작과 같은 Wi-Fi 연결 여부 확인.
- 허리/몸통 고정 위치, 고정 상태, 달리기 중 오검출, 점프 누락, 착지 충격 중복 판정, 어린이별 보정값을 반복 측정.
- 실제 점프 시작부터 TV 캐릭터 반응까지 고속 촬영으로 측정. 현재 왕복 지연과 수신→렌더 값은 전체 지연을 뜻하지 않는다.
- 지금의 수동 연결 정보 교환은 보호자가 시험을 준비하는 절차다. 실제 제품 사용에는 간단한 기기 연결 절차가 필요하다.
- 직접 연결은 같은 Wi-Fi에서의 POC 범위다. 공유기에서 기기 간 통신을 막거나 브라우저가 로컬 후보를 연결하지 못하면 실패할 수 있다.

**현재 판단: 추가 POC 필요.** 버튼 입력을 기기 간 전송해 러너에 반영하는 경로는 확인했다. 몸에 고정한 실제 휴대폰의 점프 인식률, 유아 착용 안전성, TV까지의 지연은 아직 결론을 낼 근거가 없다.
